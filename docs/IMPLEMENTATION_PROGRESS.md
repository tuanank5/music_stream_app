# Báo cáo tiến độ backend và UI

Cập nhật: 2026-11-05. Theo [đặc tả đã chốt](BACKEND_AND_UI_REQUIREMENTS.md). File này là nơi cập nhật checkpoint từ đây; README chỉ giữ hướng dẫn vận hành và liên kết. “Đã làm” không đồng nghĩa đã nghiệm thu trên thiết bị thật hoặc đã deploy cloud.

## Trạng thái tổng thể

**Đang triển khai, chưa hoàn thành toàn bộ.** Backend Express 5 đã chạy local và qua kiểm thử; schema vẫn còn bản cũ. Chưa đủ điều kiện bàn giao import dữ liệu cloud theo schema mục tiêu.

## Checkpoint hiện tại

- Catalog lists chuyển sang GET `/catalog/public-songs`, `/catalog/own-songs`, `/catalog/artists`, `/catalog/albums`, `/catalog/follower-songs/:id`; filter query trước phân trang, document ID cursor, tối đa 50/trang. Public seed giữ giới hạn 20 và không dùng để tính toàn bộ Home/Charts/Search. Own lấy UID token; follower endpoint kiểm tra relation và hydrate bài qua readSong để revalidate quyền/chủ active. Artists DTO ghép users/publicProfiles counters; albums loại private/deleting/chủ inactive. DTO không email.
- watchSongs/watchArtists/watchAlbums/watchArtistFollowerSongs dùng loader API theo UID/path thay onSnapshot. Backend write events invalidation các nguồn catalog liên quan sau song/album/profile/follow mutations; bỏ invalidation riêng trùng ở SongRow. Xóa watchFollowedSongs và chartService legacy không còn caller (không xóa collection charts). CatalogService chỉ còn Firebase SDK sinh ID local, không query/read document.
- Giới hạn: provider vẫn đọc đủ các trang own/artists/albums/follower để tương thích UI cũ, có thể nhiều reads/request và chạm rate limit khi graph lớn; hydration hiện nhiều read lặp, cần batch/cache. Đây chưa phải push/realtime từ thiết bị khác. API query hiện tương thích visibility/isPublished cũ, migration isPublic/counters chưa thực hiện. Các index cấu hình hiện có cho public/follower query chưa deploy cloud; Emulator không chứng minh đủ index cloud.
- Kiểm chứng catalog: 61/61 tests và 35/35 integration/Rules đạt; test public seed ≤20, private album bị loại, artists phân trang/whitelist, own scope bỏ qua UID query, follower subscription thật qua API. Rà src không còn onSnapshot/getDoc/query/runTransaction nghiệp vụ; Firebase SDK còn dùng init/emulator và sinh ID local. Rules legacy một số collection vẫn cho client cũ đọc/ghi theo owner, cần đóng và cập nhật test vận hành trước rollout; không coi schema/security rollout đã xong. Emulator đã tắt, chưa deploy/migrate cloud/device QA.

- Chi tiết bài chuyển getReadableSong/watchSong sang GET `/songs/:id` và `/song-items/:id`. Router đọc source mới nhất, kiểm tra bài/chủ active, quyền owner/public và tương thích followers/unlisted; DTO whitelist, chỉ ghép tên album owner/công khai, không lộ tên album riêng qua bài public. getReadableSong trả null khi 404 và giữ error code permission-denied cho caller cũ khi 403. Linked song trong DataContext dùng loader API theo UID/ID thay Firestore document listener; đổi ảnh/gỡ bài của mình invalidation nguồn chi tiết sau API thành công.
- Chưa chuyển các subscription danh sách watchSongs/watchArtists/watchAlbums/watchArtistFollowerSongs. Chi tiết không còn realtime thay đổi từ thiết bị khác; quyền được kiểm tra lại khi gọi API và mỗi heartbeat playback. Catalog shared vẫn listener, chưa coi chuyển toàn bộ catalog hoàn thành. Không thay schema hoặc nguồn audioKey trong checkpoint này.
- Kiểm chứng song detail API: lint/typecheck, 61/61 tests và 35/35 integration/Rules đạt. Integration kiểm tra public song không lộ tên album private/email, private trả 403 với viewer nhưng owner xem được, linked subscription thật qua API, chủ inactive/missing trả null; follow-only song mất quyền sau unfollow. Tách ca Search request-heavy sang server test riêng sau khi suite chạm rate limit chung, không thay giới hạn production. Emulator đã tắt; chưa deploy cloud/device QA.

- Player đã gọi createPlaybackSession → POST playback thay transaction client. usePlaybackHistory lấy mẫu mỗi giây; bỏ pause/buffering/jump/time gap >3s, gửi khoảng [start,end] và progress, không gửi duration/listenedSeconds/completed. Flush khoảng 10 giây và khi đổi playing/finish/cleanup; xét trạng thái playing trước đó để tránh cộng thời gian đứng. Sender giữ packet/sequence nguyên khi retry, giữ thêm mẫu mới ở hàng đợi, reset session và bỏ coverage cũ khi server 409. Ràng buộc phiên Auth bằng object user, không gửi vào phiên đăng nhập thay thế.
- Queue giới hạn 360 interval chờ và tối đa 120 interval/request; quá bộ nhớ bỏ mẫu mới thay vì cộng bù sau. Mạng lỗi lâu/đóng ứng dụng có thể mất thời gian chưa gửi; chưa durable outbox. Một phần cuối bài có thể không được thu khi native engine đổi bài quá nhanh, cần device QA cho bài ngắn/auto-next/background. Session server RAM/restart/đa instance vẫn theo giới hạn checkpoint trước.
- Firestore Rules đã chặn toàn bộ client ghi history/playReceipts và bỏ nhánh countedPlay để không tự tăng playCount. Bỏ transaction Firestore khỏi historyService; SDK tại đây chỉ sinh history ID local. Phải triển khai backend/client/Rules đồng bộ; client cũ sẽ bị từ chối ghi. API policy 30s/80% được nối vào app code, chưa deploy cloud hoặc nghiệm thu trên thiết bị thật.
- Kiểm chứng nối player: lint/typecheck, 61/61 tests và 34/34 integration/Rules đạt. Thêm kiểm thử queue retry đúng packet, giữ mẫu mới khi lỗi, reset ID/coverage khi 409; thay hai Rules tests counting legacy thành một nhóm từ chối mọi ghi history/receipt/count của client. Integration API counting vẫn đạt với Rules đóng. Còn thiếu test lifecycle đầy đủ của usePlaybackHistory/native audio; demo audioKey cũ có duration không khớp file, không dùng nghiệm thu counting. Emulator đã tắt, chưa deploy/migrate cloud.

- Thêm POST `/playback/:historyId` dùng policy mới. Body whitelist songId/sequence/progressSeconds/ranges; sequence 0 mở phiên với progress=0/ranges rỗng. Server kiểm tra UID/active/quyền bài/chủ và duration từ Firestore, không nhận duration/listened/completed do client tự khai. Transaction cập nhật history/song/receipt và chỉ cộng một lần mỗi phiên/cooldown 30s. Timestamp từ clock server; đọc phiên playedAt mới nhất của UID để giới hạn credit tổng nhiều phiên theo thời gian thực, bên cạnh khóa hàng đợi UID trong process.
- Coverage/sequence giữ trong RAM, tối đa 5.000 phiên, hết hạn sau 30 phút không cập nhật; đầy trả 503, không tự evict phiên active. Mất state do restart/đổi instance/hết hạn trả 409, không phục hồi thiếu coverage hoặc tái sử dụng history ID cũ. Client cần tạo phiên mới và reset sequence/coverage. Không thêm field/collection telemetry. Đây là phương án fail-closed, chưa phải sticky session/durable session đa instance.
- API playback đã đăng ký nhưng **player chưa gọi**, historyService/usePlaybackHistory vẫn luồng Firestore cũ. Chưa khóa Rules counting cũ vì cần rollout client đồng bộ. Do đó chưa coi ứng dụng đã chuyển policy 30s/80% hoặc đã chặn toàn bộ ghi giả qua legacy Rules. Bước tiếp theo: thu thập interval thực tế trong player, retry cùng sequence, xử lý 409/restart, đổi savePlayback sang API và đóng Rules legacy.
- Kiểm chứng API playback: lint/typecheck, 59/59 tests và 35/35 integration/Rules đạt. Test Router thật với Firestore Emulator và clock server được điều khiển trong test: reject private/duration giả, init/retry, từ chối thời gian chưa trôi, concurrent duplicate chỉ cộng một lượt, seek cuối không completed, sai thứ tự/phiên mất/đổi bài trả 409. Clock kiểm thử chỉ truyền qua factory server, không nhận từ request. Emulator đã tắt; chưa cloud deploy/device QA hoặc benchmark nhiều instance.

- Chuẩn bị playback backend: thêm `playback-policy.cjs` tính thời gian và hợp nhất các khoảng nội dung đã nghe. Packet chỉ có sequence/progressSeconds/ranges; từ chối field tự khai completed/listenedSeconds, interval âm/NaN/quá 3 giây, tổng thời gian lớn hơn elapsed do server đo; sequence lặp không cộng thêm, sequence nhảy trả 409. Coverage được hợp nhất để nghe lặp một đoạn không giả 80%; completed cần phủ ≥80% và tới cuối, giữ cờ đã đạt. Counting policy bài ≥30s cần nghe 30s, bài <30s cần completed, cooldown receipt 30s và mỗi phiên một lượt.
- Đây mới là lớp tính toán thuần có kiểm thử, **chưa nối vào Router, transaction history/song/receipt hoặc player**. State coverage/sequence phải được server quản lý, elapsed không lấy từ client, khóa đồng thời nhiều thiết bị và quy trình retry/restart còn phải triển khai trước khi bật. Policy cũ vẫn đang chạy; không coi module này là đã hoàn thành chuyển playback API. Không thêm collection/thuộc tính hoặc thay dữ liệu trong checkpoint này.

## Giới hạn quan trọng

- Auth và Firestore không có transaction chung. Deactivate ghi inactive trước rồi disable/revoke: lỗi giữa các bước cần đối soát/retry, không coi là đã hoàn tất. Các URL media đã biết không được Firestore bảo vệ.
